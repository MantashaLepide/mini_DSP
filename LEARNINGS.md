# What I learned

After each phase, the Agent asks the developer for one useful learning and records it briefly.

- **Planning:**
- **Detection:** Validate whole candidates and token boundaries before accepting matches; normalize only after capturing a candidate. Luhn validates a checksum, not account issuance. NINO checks establish format only. Treat emails as atomic to prevent double-counting their numeric contents.
- **Repeated-match scalability:** Disjoint candidate spans per detector pass allow linear bitmap overlap checks while preserving detector precedence, at one byte per input UTF-16 code unit. Stress tests should assert exact outputs and report timings without machine-dependent timing thresholds; final sorting still costs O(k log k).
- **Security/persistence:** Authenticate before reading uploads; cap actual streamed bytes before multipart parsing, not just Content-Length. Fixed buffers bound memory independently of chunk count. Filenames can contain sensitive data, so use generated display names. Derive ownership inside an atomic database function and enforce parent ownership with a composite foreign key; fake-client tests cannot prove RLS or rollback.
- **UI:**
- **Testing/deployment:** Native Node TypeScript tests initially numbered 38; the scalability suite expanded this to 39. The scaffold milestone separately passed all 39 tests, strict typecheck, and a local production build. None establishes a Vercel deployment or secure integration.
- **Scaffold:** Pin declaration packages as well as runtime packages. Include .mts tests and allowImportingTsExtensions with noEmit; run next typegen before tsc for fresh-checkout declarations. Next 16.4 enables agent-file generation by default; agentRules: false keeps the minimal scaffold free of those generated instructions.
- **Auth/upload tests:** Native Node strip-only mode cannot execute TypeScript parameter properties. The new 53-test suite and local build pass, but live Supabase/email/cookie and SQL checks remain unverified. Fail-closed smoke checks must distinguish missing configuration (503) from rejected origins (403); terminal tools may rewrite inline JavaScript logical operators, so use Node assertions.
- **Live auth verification:** Check configuration presence without echoing values. Signup, PKCE, refresh, and signout need configured project settings plus a confirmation inbox; absent values mean no remote tests and no success claims. Keep upload disabled until the migration and persistence path are reviewed and verified; filename retention is an explicit privacy/product decision.
- **Auth check status:** Config/key format checks passed; Auth settings returned 200 and unauthenticated session returned 401. Signup returned only generic 202; the handler discards the `signUp` error, so provider or network failures are hidden. Node's bundled CA store rejected the Supabase TLS chain (fetch failed) while Windows trust succeeded; with `--use-system-ca` a synthetic sign-in returned `invalid_credentials`, so the first signup likely never created an account (unverified). Signup via PowerShell has no cookie jar, so PKCE verifier cookies would not reach the user's browser; a browser-initiated signup is needed. Signin, refresh, and signout remain unverified.
- **Auth result:** A 400 from the app means validation rejected the request before Supabase. A 401 with `invalid_credentials` from Supabase means a wrong password or no account. Log provider error name, status, and code, never messages, to tell them apart. Setting a password in the dashboard for an existing confirmed user unblocked sign-in when the earlier sign-up password was unknown.
- **What I'd do differently:** Define ambiguous whitespace-only numeric separation explicitly before integration. Use bounded Unicode-aware lookarounds for adjacent characters instead of copying the whole input per match. PowerShell 5.1 needs `[DateTime]::UtcNow`, not `Get-Date -AsUTC`.
